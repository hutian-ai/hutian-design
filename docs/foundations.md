# 主题与布局基础

来自 Hutian 既有规范，保持 VoltAgent 固定基线；业务导航与数据归属由调用方负责。

## 1. 设计定位

hutian Web 是直接对齐 VoltAgent/VoltOps 的 Agent 工作站，不是营销首页、聊天玩具或游戏 HUD。它包含两类共享
同一视觉与 primitive 的工作面：World 工作区服务拥有者和成员；平台工程工作区服务开发、运行、部署和排障人员。

设计优先级依次为：

1. 权威事实、对象关系和当前状态清楚；
2. 下一步可执行动作明确；
3. 中等偏紧凑的信息密度适合长时间工作；
4. 保留工程系统的技术感，不用装饰代替信息。

视觉语言直接采用 VoltAgent 的近黑画布、低对比边线、紧凑圆角和 `#00d992` 绿色信号。产品的辨识度来自 World cursor、因果
世界线、冻结版本和行为诊断等真实结构，而不是通用 AI 装饰。

## 2. 核心原则

### 2.1 秩序优先

层级通过稳定网格、间距、字号、明度和 1px 边线建立，默认不依赖阴影。World、成员、工作、会话、世界线
和诊断必须有可预测的阅读结构。

### 2.2 单一强调色

`accent` 是唯一品牌强调色，只用于：

- 当前导航、焦点和选中状态；
- 页面唯一主操作；
- 正常运行、完成和实时连接；
- 少量 cursor、关系或执行信号。

不得把强调色用于大段正文、大面积背景、无意义描边或装饰性光晕。

### 2.2.1 品牌图形

正式图形标识使用 `apps/web/public/brand/hutian-mark.png`。该资产自带的近黑底与青绿色渐变是仅限 Logo 本体的
品牌例外，不得延伸为页面背景、按钮、边框或装饰光晕。工作站侧栏直接呈现 32px 正方形标识并保留相邻的小写
`hutian` 字标，不再叠加 Accent 底座或使用通用 Orbit 代替；收起态仍须保留可访问名称。其他位置的 Orbit 若表达
“概览”等具体功能语义，继续按功能图标使用，不视为品牌标识。

### 2.3 暗色但不糊

Canvas、Surface 和 Surface Raised 依靠轻微明度差分层。普通面板使用 `Surface + Line`；嵌套区域优先使用
背景差或单侧分隔线，避免每层都套完整卡片。

不使用大面积毛玻璃、重阴影、霓虹泛光、多色渐变或浮起位移动画。

### 2.4 管理语义优先

用户可见业务内容、状态、错误和操作使用自然中文。以下内容可以保留英文：

- 产品名和技术品牌：hutian、Next.js、DBOS、Centrifugo、AG-UI；
- 协议与缩写：API、CAS、SSR；
- 领域证据与机器标识：ActorRevision、WorldEvent、cursor、ID。

`Actor` 在界面统一显示为“成员”，但路由、Contract、Schema、事件与代码标识仍使用 Actor。

### 2.5 权威状态优先

界面状态来自 API 或可重建 Projection。客户端临时状态只能改善输入体验；服务端拒绝后必须显示可恢复的
中文反馈。版本冲突不得静默覆盖，外部副作用不得用动画或 toast 冒充完成。

### 2.6 交互架构与技术权威分离

同一份权威事实不等于只能放在同一个页面。Web 必须按用户任务组织工作区，再从 Core API 或可重建 Projection 读取同一份事实：

- “世界线”负责按发生顺序观察、筛选和追溯世界事件；
- “沟通”负责选择会话、阅读消息和持续发送，不得被降级为世界线中的一个筛选 Tab；
- 世界线中的沟通事件可以跳转到沟通工作区，但不得在历史页内嵌完整聊天工作台；
- 独立工作区只改变导航与交互结构，不得因此建立第二套 Conversation、Message、cursor 或客户端业务账本。

## 3. 颜色与边线

| 角色 | 值 | 用途 |
| --- | --- | --- |
| Canvas | `#101010` | 页面主背景 |
| Surface | `#1a1a1a` | 面板、卡片、输入区 |
| Surface Raised | `#202124` | 次级操作、轻度抬升区域 |
| Surface Active | `#242927` | 导航、列表悬停和选中 |
| Line | `#2b2d2f` | 默认 1px 分隔线和边框 |
| Line Strong | `#3d3a39` | 焦点前的高一级边界 |
| Text | `#f2f2f2` | 标题与正文 |
| Text Muted | `#bdbdbd` | 说明与次要状态 |
| Text Faint | `#818783` | 元数据与机器标识 |
| Accent | `#00d992` | 主操作、选中、正常与完成 |
| Warning | `#f2c94c` | 排队、等待与冲突 |
| Danger | `#ef6b67` | 失败、阻塞与危险动作 |

边线规则：

- 普通面板与表单控件只使用 1px `Line`；
- hover 最多提升为 `Line Strong` 或改变背景，不改成白色；
- 所有 shadcn/ui、Radix UI 与 assistant-ui primitive 的边框必须继承 `--border`/`--color-border`；
- 不允许 `border-color: currentColor` 回落，因为正文色会产生亮白框；
- 表格使用外层单一边界和行分隔线，不给每个单元格画完整方框；
- 焦点使用 Accent outline/ring，不能靠增粗白边表达。

## 4. 字体与信息层级

界面使用 Inter 与系统无衬线回退。中文使用系统字体，普通正文不用等宽字体。模型名、版本、cursor、运行编号
和不可变 ID 才使用 Mono。

- 页面标题：25–34px，中等字重，紧凑字距；
- 区块标题：14–16px，半粗；
- 正文：12–14px，行高至少 1.5；
- 元数据：9–10px，低强调色；
- eyebrow：9px，可用适度字距，不强制英文全大写。

长 ID 默认压缩，完整值只在诊断、复制或详情场景提供。技术枚举通过统一映射展示中文。

### 5.2 信息密度

这是操作型产品，采用中等偏紧凑密度：

- 列表行高约 60–68px；
- 面板标题区 56–68px；
- 面板内容内边距 14–18px；
- 控件高度 32–40px；
- 同类卡片间距 10–12px。

受众由工作面决定：World 工作区面向拥有者和成员，页面首先回答“现在能做什么、谁在工作、是否正常、下一步是什么”；
平台工程工作区面向开发、运行、部署和排障人员，日志、Trace、Runtime、Deployment、Agent Server、Tunnel、MCP、成本和
告警可以把 Driver、Adapter、placement、Grant、协议、Endpoint、内部 ID、JSON 与原始错误作为一等信息展示。
两类工作面都不得用假统计、假图表或工程 TODO 填空；权威数据不存在时省略模块或展示与受众匹配的空态。

头像或字母标记只辅助识别，不作为视觉主角。成员通用设置使用现有 Input 编辑可选 HTTPS 头像地址或本站静态头像路径；目录、协作树和详情复用 AvatarImage + AvatarFallback，以 object-cover 展示并禁发 Referer，留空或加载失败显示姓名占位。成员页先让用户扫描状态、职业、职业说明摘要与版本，再进入配置。

## 7. 响应式规则

hutian Web 的默认设计与真实浏览器基线是 PC 工作站。探索期先用源码、静态检查和受影响测试获得反馈；只有页面布局或
关键交互发生变化时，才在当前最短真实路径中做一次桌面浏览器 smoke，检查主要路径、视觉层级、交互、console 与页面级
溢出。固定截图、axe 与跨页面矩阵留到视觉专项或里程碑稳定化；除非 Owner 明确提出，后续不要求为每次改动重复执行手机或
窄屏真实浏览器验收。
以下窄屏规则仍是实现约束，不能因为默认不做移动端验收而主动破坏基本响应式布局。

### 桌面：`> 820px`

- 展示完整侧边栏和世界工具栏；
- 成员目录使用横向表格；
- 搜索和状态筛选位于同一行；
- 多组配置使用双列表单。

### 平板与手机：`≤ 820px`

- 桌面侧边栏隐藏，顶部保留 Toggle sidebar；完整导航使用覆盖式 Drawer，不重组为拥挤横向导航；
- 内容横向留白降至 15px；
- 工具带重组为纵向；
- 多组配置重组为单列；
- 宽表格只能在自身容器内横向滚动，不能让整个页面横向滚动；
- 所有关键触控目标至少 42px，图标不能是唯一状态表达。

Drawer 打开时锁住背景滚动，支持遮罩和 `Escape` 关闭，关闭后焦点回触发器。hover 才出现的关键动作必须在触控设备上
提供常驻入口。Graph、Table、Code 与 Diff 各自在自身容器内滚动或缩放，`body` 不得横向溢出。

## 8. 动效

动效只解释状态变化：

- 控件 hover/focus：120–160ms；
- 面板或编辑区出现：160–220ms；
- 实时连接、cursor 更新可用低幅状态变化；
- 遵守 `prefers-reduced-motion`。

不使用弹跳、漂浮、持续脉冲、打字机装饰或大面积背景动画。

## 9. 可访问性

- 正文与背景达到 WCAG AA；
- 所有交互支持键盘访问和可见焦点；
- 图标按钮有 accessible name；
- 状态同时使用文字；
- 表单错误与相关输入建立语义关联；
- Dialog、Sheet、Menu、Popover 使用正确 role、标题、焦点圈和关闭后焦点恢复；
- 展开/收起控件暴露 `aria-expanded`；动态结果按紧急程度进入 `role=status` 或 `role=alert`；
- 图表、Diff 和拓扑选择提供非颜色表达与可读摘要；
- 桌面和移动端保持合理点击区域；
- 表格在窄屏有明确滚动容器，不截断操作列且不污染页面宽度。

## 10. 应做与禁止

应做：

- 先复用本文件的 token、间距和组件规则；
- 用排版、留白、明度和薄边线建立层级；
- 让主要动作明显且克制；
- 用真实 World、成员、工作、事件与执行结构塑造界面；
- 视觉规范变化时同步更新本文件与 Docs Hub 技术设计。

禁止：

- 不引入第二套主色；
- 不使用紫蓝 AI 渐变、玻璃拟态、环境色 blob；
- 不使用厚重阴影和亮白描边；
- 不把所有控件做成胶囊或超大圆角；
- 不把技术错误、原始枚举或英文业务状态直接交给用户；
- 不用大卡片网格替代需要快速扫描的目录列表；
- 不复制 Empire 的 Workspace、Member、Company 或 Employee 领域语义。
